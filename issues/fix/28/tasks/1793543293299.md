# 이름 변경 배포물과 전체 테스트 검증

Python 3.13 임시 환경에서 core 및 Gunicorn·Uvicorn adapter wheel과 sdist를 새 `DefChord` 배포명으로 빌드했다. 생성된 6개 배포물 모두 `twine check --strict`를 통과했다.

`python .github/scripts/check_distributions.py --editable --dist-dir <임시 배포물 디렉터리>` 검증에서 패키지 소유권, sdist 재빌드, 네 가지 adapter 설치 조합과 editable 설치 수명주기 검증이 통과했다.

CI와 같은 방식으로 빌드된 wheel을 별도의 깨끗한 Python 3.13 환경에 설치하고, 저장소 외부의 작업 디렉터리에서 `python -m unittest discover -s <저장소>/tests -p 'test_*.py' -v`를 실행했다. 전체 253개 테스트가 통과했고 5개는 기존 조건에 따라 건너뛰었다. 저장소 폴더와 동일한 `DefChord` 이름이 Python import namespace와 충돌하지 않도록 테스트는 저장소 외부에서 실행했다.

VS Code 테스트 검색은 이 저장소의 테스트 항목을 발견하지 못해 실행되지 않았다. 대신 저장소 CI에서 사용하는 `unittest` 명령으로 전체 테스트를 검증했다. PyPI JSON API에서 `DefChord`, `DefChord-Gunicorn`, `DefChord-Uvicorn`은 모두 404였으며, 게시나 예약은 수행하지 않았다.

CI release preparation 테스트도 실행했다. `.dev/scripts/tests` 13개와 `.github/scripts/tests` 14개가 모두 통과했다.

변경 공백 검사는 `git diff --check`로 통과했다. 테스트 실행을 위해 만든 임시 가상환경과 검증 배포물은 저장소 밖에 두었다. 저장소 안의 이전 빌드·배포 산출물 정리는 [후속 작업 기록](./1793544105753.md)에 남겼다.
