# 최신 리뷰 문제 재현과 수정 검증

[bytecode 의견](https://github.com/yong5eon/DefChord/pull/26#discussion_r4434766435)과 [로컬 wheel 의견](https://github.com/yong5eon/DefChord/pull/26#discussion_r4434766443)을 확인했다. 하드 링크 교체 뒤 후속 링크를 실패시키고 소스 크기·mtime을 같게 유지한 회귀 테스트가 수정 전 새 프로세스에서 `VALUE = 1`을 출력하여 실패했다. 수정 후 캐시가 즉시 없어지고 재시도 후 `VALUE = 2`를 읽는다.

동일 버전의 `99` 빌드 번호 경쟁 wheel을 임시 디렉터리에 만들어 실제 pip의 `--dry-run --ignore-installed --no-index --no-deps --report`로 검증했다. 이름·버전 요청은 경쟁 파일을 선택하지만 새 명시적 요구사항은 코어와 모든 선택 구현체의 로컬 URI를 선택한다. 이 재현은 외부 통신이나 설치 환경 변경 없이 실행한다.

최소 Python 3.9의 개발용 테스트 13개와 워크플로 테스트 14개, 변경 Python 타입 검사를 통과했다. Linux Python 3.9에서도 같은 두 discovery 명령으로 27개를 통과했다.

저장소 루트에서 검증 버전 `0.2.0`을 환경변수로 지정하고 `python .github/scripts/build_distributions.py --outdir dist/review-fixes --no-isolation` 및 `python .github/scripts/check_distributions.py --dist-dir dist/review-fixes --editable`를 실행했다. 파일 소유권·독립 sdist 재빌드·네 설치 조합·순차 extra 추가·설치 수명주기·editable 선택 교체·두 환경 격리를 모두 통과했다. 초기 통합 검사 후 캐시 디렉터리 정리를 기존의 Python 캐시 디렉터리 범위로 제한하는 최종 조정을 반영하여 배포물 재빌드와 전체 통합 검사를 다시 통과했다.

sdist helper가 최종 소스와 바이트 단위로 일치하고 일반 wheel의 제품 파일은 이전 배포물과 동일함을 확인했다. 한영 명령·문서 구조·링크·개인 경로·구문 및 `git diff --check`를 확인했다. 공유 checker 전체의 바이트 동일성 검사는 기존 파일별 차이가 있어 비교 범위를 공통 helper와 테스트로 제한했다. 제품 전체 테스트·실제 원격 CI·게시를 이번 단계에서 실행하지 않았고 커밋·푸시는 수행하지 않았다.
