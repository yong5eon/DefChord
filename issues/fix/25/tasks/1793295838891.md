# 최소 지원 버전과 이전 통합 배포 전환 검증

Python 3.9에서 코어·Gunicorn·Uvicorn wheel/sdist 빌드, 독립 sdist 재빌드, 네 설치 조합, 파일 소유권, 추가 설치·재설치·구현체 제거 검사를 통과했다. `python scripts/check_distributions.py --dist-dir dist/minimum --editable`로 코어·각 구현체의 기존 소스 변경 반영과 새 코어 파일 추가 후 재설치까지 확인했다. 릴리즈 준비 단위 테스트도 6개 통과했다.

첫 최소 버전 검증에서는 기본 pip 22.0.4가 패키지 인덱스 응답을 처리하지 못했다. Python 3.9 호환 pip로 검증 환경을 갱신하고, 새 자식 환경도 `pip>=23`을 확보하도록 도구를 보완한 뒤 전체 검사를 통과했다.

변경 전 `HEAD`의 소스로 통합 wheel을 빌드해 설치했다. 양쪽 어댑터 파일 존재를 확인한 후 기존 코어를 제거하고 새 코어와 Gunicorn만 설치했다. Gunicorn import, Uvicorn 부재 및 `pip check`를 확인했다. 이 검사는 제거 후 전환 경로이며 통합 버전 위에 단순 덮어 설치하는 경로가 아니다.

다음 추가 검사도 통과했다.

- 구현체 sdist의 빌드 대상을 `core`로 변경하려는 요청 거부
- `python scripts/build_distributions.py --wheel --no-isolation --outdir ...`의 wheel 전용 빌드: wheel 3개, sdist 없음
- `python -m twine check --strict`로 wheel 3개와 sdist 3개 검사
- YAML 로딩·내장 Python 구문, 변경 Markdown의 구조·상대 링크·개인 경로 검사 및 `git diff --check`

실제 Linux/Gunicorn 실행, 전체 원격 CI, PyPI 게시 권한 및 실제 게시 검증은 수행하지 않았다. 지원 범위 전체 런타임을 로컬에서 검증한 것은 아니며 Python 3.9·3.13 결과이다.
