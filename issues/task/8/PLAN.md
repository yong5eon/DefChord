# 모든 PR 테스트 실행 작업 계획

## 목표

[요구사항 명세서](./REQUIREMENTS.md)에 맞게 모든 PR과 `master` push에서 동일한 Python 테스트 매트릭스를 실행하고, 버저닝·릴리즈 작업은 `master` push 전용으로 분리한다.

## 작업 단계

1. 현재 CI 트리거와 job 간 의존성을 확인한다.
2. `pull_request` 트리거에서 대상 브랜치 필터를 제거하고 `push`를 `master`로 제한한다.
3. 테스트 job의 변경 경로 조건을 제거해 모든 PR과 `master` push에서 테스트되게 한다.
4. 버전 계획, 릴리즈 노트 수집·보관, 배포 산출물 보관 및 배포 단계가 `master` push에서만 실행되는지 확인한다.
5. YAML 파싱과 워크플로 조건을 검증하고, 실제 GitHub Actions 실행 여부는 저장소의 기본 브랜치에 변경이 반영된 뒤 확인한다.

## 검증 기준

- YAML 문법 검증을 통과한다.
- 정적 확인으로 PR 테스트에 실행 제한 조건이 없음을 확인한다.
- 모든 릴리즈 관련 단계가 `push`와 `refs/heads/master` 조건에 한정됨을 확인한다.
- PR 테스트용 패키지 빌드·설치는 유지되며, PR에서 릴리즈 artifact 생성·배포 작업을 수행하지 않음을 확인한다.
