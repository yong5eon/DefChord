# 요청 오류 응답 사용자 정의

요청 처리 중 발생한 오류를 애플리케이션 정책에 맞는 HTTP 응답으로 처리할 수 있습니다. `RequestRunner`, Extension, Application 오류 훅에서 `Response`를 반환하면 해당 응답이 채택되고, `None`을 반환하면 기존 오류 전파와 adapter 기본 응답 동작이 유지됩니다.

여러 오류 훅을 등록하면 설정 순서대로 실행되며, 처음 `Response`를 반환한 뒤 같은 계층의 나머지 오류 훅은 실행되지 않습니다. 복구 응답은 실패한 같은 계층의 응답 훅을 다시 거치지 않지만 바깥 계층의 정상 응답 처리 흐름은 이어집니다.

직접 출력이나 스트리밍 응답 전송이 시작된 뒤에는 이미 보낸 상태 코드와 본문을 오류 응답으로 교체할 수 없습니다. 오류 훅의 사용법과 운영상 주의사항은 [요청 오류 처리 매뉴얼](../../../docs/ErrorHandling.md)을 참고하세요.

저장소 통합 샘플에 `GET /api/run/error` 예제를 추가했습니다. 이 endpoint는 의도적인 오류를 `RequestRunner` 오류 훅이 HTTP 418 사용자 정의 응답으로 처리하는 모습을 보여줍니다.
